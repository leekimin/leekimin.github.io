## 컨테이너까지는 순조로웠다

Docker를 도입하면 개발 환경과 운영 환경이 같아집니다. 이미지 하나를 만들어 어디서든 동일하게 실행할 수 있죠. 그런데 실무에서 컨테이너가 열 개, 서른 개로 늘고 서버가 세 대 이상이 되는 순간 성격이 전혀 다른 문제가 시작됩니다.

- 새벽 3시에 컨테이너가 OOM으로 죽으면 누가 다시 띄우나요?
- 트래픽이 두 배가 되면 몇 개를 더 띄우고, 로드밸런서에는 어떻게 등록하나요?
- 새 버전을 배포하는 동안에도 서비스는 멈추면 안 됩니다. 어떻게 하죠?
- 서버 한 대가 통째로 내려가면 그 위에 있던 컨테이너들은 어떻게 되나요?

이 질문들의 공통점은 **컨테이너를 만드는 문제가 아니라 계속 돌아가게 유지하는 문제**라는 점입니다. 쿠버네티스는 정확히 이 지점에서 출발합니다.

## 명령형 운영의 한계

많은 팀이 처음에는 쉘 스크립트로 버팁니다.

```bash
# 명령형: 무엇을 할지 하나하나 지시한다
ssh node-1 docker run -d --name api-1 myapp:1.2
ssh node-2 docker run -d --name api-2 myapp:1.2
ssh node-3 docker run -d --name api-3 myapp:1.2
# 하나가 죽으면? 다시 띄우는 건 결국 사람의 몫
```

이 방식의 근본 문제는 **현재 상태를 아무도 모른다**는 것입니다. 스크립트는 실행된 순간의 동작만 기술할 뿐, 지금 몇 개가 살아 있는지, 어떤 버전이 떠 있는지는 사람이 직접 확인해야 합니다. 장애는 늘 사람이 자고 있을 때 납니다.

## 선언형으로의 전환

쿠버네티스는 접근을 뒤집습니다. 절차가 아니라 **원하는 상태(desired state)** 를 선언합니다.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 3          # 항상 3개가 떠 있어야 한다
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
        - name: api
          image: myapp:1.2
```

여기서 `replicas: 3`은 명령이 아니라 약속입니다. 컨트롤러는 클러스터의 현재 상태를 끊임없이 관찰하면서 선언된 상태와 다르면 그 차이를 스스로 메웁니다. 이 반복 과정을 **리컨실리에이션 루프(reconciliation loop)** 라고 부르며, 쿠버네티스 전체를 관통하는 단 하나의 핵심 개념입니다.

노드 하나가 죽어 Pod가 2개로 줄면, 컨트롤러가 이를 감지하고 남은 노드에 1개를 새로 스케줄링합니다. 사람이 개입하지 않습니다. 이미지를 `myapp:1.3`으로 바꿔 다시 적용하면, 기존 Pod를 하나씩 교체하며 무중단으로 배포합니다.

```bash
kubectl apply -f deployment.yaml   # 원하는 상태를 등록
kubectl get pods -l app=api        # 실제 상태를 조회
```

## 쿠버네티스가 대신 해주는 일

| 운영 과제 | 쿠버네티스의 답 |
|---|---|
| 죽은 프로세스 복구 | 자가 치유(self-healing) |
| 트래픽 증가 대응 | 오토스케일링(HPA) |
| 인스턴스 주소 관리 | 서비스 디스커버리와 내부 DNS |
| 무중단 배포 | 롤링 업데이트와 즉시 롤백 |
| 환경별 설정 분리 | ConfigMap과 Secret |
| 어느 서버에 배치할지 | 리소스 기반 스케줄러 |

## 오늘의 정리

쿠버네티스는 컨테이너 실행 도구가 아니라 **컨테이너 운영을 자동화하는 상태 관리 시스템**입니다. 배울 때 모든 리소스 종류를 외우려 하면 금방 지칩니다. 대신 어떤 리소스를 보든 이렇게 물어보세요. *이건 어떤 상태를 선언하는 것이고, 누가 그 상태를 맞춰주는가?*

다음 회차에서는 이 리컨실리에이션을 실제로 수행하는 주체, 즉 컨트롤 플레인과 워커 노드의 구성 요소를 하나씩 뜯어봅니다.
