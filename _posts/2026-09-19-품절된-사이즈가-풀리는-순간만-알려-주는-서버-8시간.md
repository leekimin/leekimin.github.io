## 순위에서 읽은 것

폴센트가 9위에 있다는 건 "떨어지면 알려 달라"는 수요가 이미 검증됐다는 뜻이다. 그런데 목록에는 유니클로, 스파오, ZARA, 무신사, 29CM, 4910처럼 옷을 파는 앱이 절반 가까이 몰려 있고, 옷에서 사람이 실제로 기다리는 건 가격보다 사이즈다. 품절된 M이 다시 풀렸는지 알려면 앱을 하나씩 열어 보는 수밖에 없다. 가격을 가로질러 보는 도구는 있는데, 재고를 가로질러 보는 도구는 이 목록에 없다.

## 만들 것

상품 URL과 원하는 옵션(사이즈, 색상)을 등록해 두면 품절에서 재입고로 바뀌는 그 전이에서만 웹훅을 쏘는 서버. 쓰는 사람은 나와 주변 몇 명이고, 화면은 등록 폼 한 장이면 충분하다. 알림은 디스코드나 슬랙 채널로 보낸다.

## 8시간 범위

- 브랜드별 파서를 어댑터 하나로 추상화하고, 공식 상품 JSON을 그대로 읽을 수 있는 두 곳만 붙인다
- 5분 주기 스케줄러가 등록된 항목만 돌고, robots.txt와 요청 간격을 지킨다
- soldout에서 instock으로 바뀐 전이에서만 발송하고, 같은 상태가 반복되면 침묵한다
- 등록과 해제 폼, 항목별 마지막 확인 시각 표시

## 스택과 시간 배분

Python, FastAPI, APScheduler, SQLite, httpx. 배포는 컨테이너 하나.

| 시간 | 할 일 |
| --- | --- |
| 0~2h | 스키마와 등록 API, 상품 페이지에서 옵션별 재고를 뽑는 어댑터 한 종 |
| 2~5h | 두 번째 어댑터, 스케줄러와 상태 전이 판정, 웹훅 발송 |
| 5~8h | 등록 폼, 실패와 차단에 대한 백오프, 실제 상품 두 개로 하루 돌려보기 |

```sql
CREATE TABLE watch (
  id INTEGER PRIMARY KEY,
  url TEXT NOT NULL,
  option TEXT NOT NULL,
  state TEXT NOT NULL DEFAULT 'unknown',
  checked_at TEXT,
  UNIQUE(url, option)
);
```
