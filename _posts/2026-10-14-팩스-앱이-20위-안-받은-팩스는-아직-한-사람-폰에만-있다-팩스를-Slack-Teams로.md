## 순위에서 읽은 것

모바일팩스 i가 6위에 있습니다. 앱 설명에도 "아직도 관공서에서는 팩스를 보내달라는 곳이 많다"는 문장이 들어 있습니다. 같은 순위에 Microsoft Teams(15위)와 Slack(19위)도 있으니, 팀이 일하는 곳은 메신저 채널입니다. 팩스 수요는 있지만, 들어온 팩스를 팀이 같이 보고 누가 처리했는지 남기는 연결 고리는 비어 있습니다.

## 만들 것

팩스 서비스의 메일 전달 기능을 켜 두면, 메일로 들어온 팩스 첨부를 받아 팀 채널에 올리는 서버입니다. 관공서나 거래처와 팩스를 주고받는 소규모 사무실이 대상입니다. 팩스가 담당자 한 명의 폰에만 머물지 않고, 미처리 건이 목록으로 남게 하는 것이 목표입니다.

## 8시간 범위

- 전용 메일함을 IMAP으로 폴링해 PDF·TIFF 첨부를 수집하고, 해시로 중복을 걸러낸다
- 첫 페이지를 PNG로 바꾸고 Tesseract 한국어 OCR로 앞 200자를 뽑는다
- Slack·Teams 수신 웹훅에 수신 시각, 앞부분 텍스트, 원본 링크를 올린다
- 미처리 팩스 목록과 '처리 완료' 버튼만 있는 웹 화면 하나를 만든다

## 스택과 시간 배분

Python, FastAPI, SQLite, imaplib, poppler(pdftoppm), Tesseract(kor), APScheduler

| 시간 | 할 일 |
| --- | --- |
| 0~2h | IMAP 폴링, 첨부 저장, 해시 중복 제거, SQLite 적재 |
| 2~5h | PDF·TIFF를 PNG로 변환, OCR 요약, Slack·Teams 웹훅 전송과 재시도 |
| 5~8h | 미처리 목록 웹 화면, 처리 완료 기록, 하루 지난 미처리 건 재알림 |

```sql
CREATE TABLE fax (
  sha256      TEXT PRIMARY KEY,
  received_at TEXT NOT NULL,
  file_path   TEXT NOT NULL,
  ocr_head    TEXT,
  posted_at   TEXT,
  done_by     TEXT,
  done_at     TEXT
);
```
