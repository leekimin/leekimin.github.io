## 순위에서 읽은 것
네이버페이(2위), 카카오페이(3위), 토스(6위)가 모두 20위 안에 있고, 카카오뱅크와 케이뱅크까지 더하면 상위권의 상당수가 돈을 보내는 앱이다. 송금은 이미 1초면 끝난다. 비어 있는 건 그 앞 단계다. 회식이나 여행이 끝난 뒤 누가 누구에게 얼마를 보내야 하는지는 여전히 누군가 엑셀이나 메모장으로 계산한다.

## 만들 것
팀 채팅방에서 쓰는 정산 봇이다. 돈을 낸 사람이 `/pay 84000 @민수 @지영`처럼 남기면 봇이 잔액을 쌓아 두고, `/settle`을 치면 송금 횟수를 줄인 '누가 누구에게 얼마' 목록을 돌려준다. 실제 송금은 각자 쓰던 페이 앱으로 하면 된다.

## 8시간 범위
- Slack 슬래시 커맨드 웹훅 두 개(/pay, /settle)와 요청 서명 검증
- 채널별 지출 기록과 잔액 계산, 1원 단위로 나누어떨어지지 않는 금액 처리
- 정산을 확정하면 해당 라운드를 마감하고 다음 기록은 새 라운드로 시작
- 라운드별 내역을 보여 주는 읽기 전용 웹 페이지 한 장

## 스택과 시간 배분
Python, FastAPI, SQLite, Slack Slash Commands

| 시간 | 할 일 |
| --- | --- |
| 0~2h | Slack 앱 등록, 서명 검증, 커맨드 파싱, expenses 테이블 |
| 2~5h | 잔액 계산, 정산 함수, 나머지 금액 처리 테스트 |
| 5~8h | 라운드 마감, 내역 웹 페이지, 배포 |

핵심은 아래 함수 하나다. 받을 돈은 양수, 낼 돈은 음수인 잔액을 받아서, 가장 많이 받을 사람과 가장 많이 낼 사람부터 짝지어 송금 목록을 만든다.

```python
def settle(bal):
    cr = sorted([v, k] for k, v in bal.items() if v > 0)
    dr = sorted([-v, k] for k, v in bal.items() if v < 0)
    while cr and dr:
        c, d = cr[-1], dr[-1]
        x = min(c[0], d[0]); c[0] -= x; d[0] -= x
        yield d[1], c[1], x
        if not c[0]: cr.pop()
        if not d[0]: dr.pop()
```
