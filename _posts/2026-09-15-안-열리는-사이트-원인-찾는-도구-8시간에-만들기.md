## 어떤 걸 만드나

특정 사이트만 안 열릴 때 원인이 DNS인지, TLS인지, 그냥 서버가 죽은 건지 알 방법이 없다. 도메인 목록을 받아 단계별로 끊어서 확인해 주는 진단 도구를 만든다. 터미널에서 돌리고 결과는 HTML 리포트 한 장으로 본다.

## 왜 만드나

회사 망에서만 안 되는 사이트가 생길 때마다 nslookup, openssl s_client, curl을 순서대로 치고 있었다. 명령어 세 개를 한 번에 묶고, 같은 도메인을 일주일 뒤 다시 쟀을 때 뭐가 달라졌는지 비교하고 싶었다.

## 8시간에 넣을 것

- 도메인당 4단계 측정: 시스템 DNS 조회, DoH 조회(Cloudflare `/dns-query`, `accept: application/dns-json`), TLS 핸드셰이크에서 발급자와 만료일, HTTP 상태코드와 응답 시간
- 결과를 `{domain, a_system, a_doh, tls_issuer, tls_not_after, http_status, elapsed_ms, ts}` 한 줄로 만들어 SQLite `runs` 테이블에 append
- CLI 두 개: `netdiag run domains.txt`, `netdiag report --last 2`
- 리포트는 정적 HTML 한 파일. 도메인 행마다 배지 네 개, 실패한 단계만 빨강. 직전 실행과 값이 다르면 그 칸에 화살표

## 시간대별 작업

| 시간 | 할 일 |
| --- | --- |
| 0~2h | 측정 함수 네 개. dnspython, ssl, httpx로 각각 짜고 도메인 하나로 손으로 확인 |
| 2~5h | asyncio 동시 실행에 타임아웃 3초, SQLite 스키마와 append, `run` 서브커맨드 |
| 5~8h | `report` 서브커맨드, HTML 템플릿은 f-string 하나면 충분, 직전 실행과 diff |

만들고 나면 손은 거의 안 간다. 주 1회 `netdiag run`을 걸어두고 리포트에 빨강이 뜰 때만 열어보면 되니 하루 10분도 안 쓴다. 범위를 넘기기 쉬운 건 브라우저 확장과 실시간 모니터링인데 둘 다 8시간 밖이다. 리포트는 파일 하나로 끝내는 게 낫다.
