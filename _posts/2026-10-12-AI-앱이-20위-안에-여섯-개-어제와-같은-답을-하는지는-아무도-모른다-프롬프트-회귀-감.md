## 순위에서 읽은 것
Claude by Anthropic, Google Gemini, ChatGPT, Grok, 에이닷, Perplexity까지 AI 어시스턴트 여섯 개가 생산성 상위 20위 안에 있습니다. 수요는 이미 검증됐습니다. 대화형 AI는 일상 도구가 됐고, 이제는 이 모델들을 API로 붙여 쓰는 서비스도 흔합니다. 그런데 모델이 업데이트된 뒤에도 내 서비스의 프롬프트가 예전처럼 동작하는지 매일 확인해 주는 도구는 이 순위에 없습니다.

## 만들 것
자주 쓰는 프롬프트와 기대 조건을 YAML로 적어 두면, 서버가 매일 밤 여러 모델 API에 같은 프롬프트를 보내고 조건을 통과하지 못한 답만 웹훅으로 알려 줍니다. LLM을 운영 코드에 붙여 쓰는 개발자를 위한, 프롬프트용 회귀 테스트입니다.

## 8시간 범위
- YAML 케이스 정의: 프롬프트, 대상 모델 목록, 검사 규칙(포함·정규식·JSON 키)
- 스케줄러가 케이스별로 호출해 응답, 지연 시간, 통과 여부를 SQLite에 저장
- 어제 통과했는데 오늘 실패한 케이스만 Slack 웹훅으로 전송
- 날짜별 통과율과 실패한 응답 원문을 보여 주는 HTML 화면 한 장

## 스택과 시간 배분
Python, httpx, APScheduler, SQLite, FastAPI + Jinja2, Slack Incoming Webhook

| 시간 | 할 일 |
| --- | --- |
| 0~2h | YAML 스키마, 모델별 호출 어댑터, 재시도와 타임아웃 |
| 2~5h | 규칙 검사, SQLite 저장, 전날 결과와 비교해 새 실패만 골라내기 |
| 5~8h | 웹훅 알림, 결과 화면, CLI로 즉시 실행하는 `run --case` 명령 |

검사 규칙은 함수 하나면 됩니다.

```python
import json, re

def check(answer: str, rule: dict) -> bool:
    kind, arg = rule["type"], rule["value"]
    if kind == "contains": return arg in answer
    if kind == "regex": return re.search(arg, answer) is not None
    if kind == "json_keys":
        try: return set(arg) <= set(json.loads(answer))
        except (ValueError, TypeError): return False
    raise ValueError(kind)
```
